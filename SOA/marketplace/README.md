# Marketplace Architecture (SOA)

## Описание проекта

В рамках домашнего задания спроектирована архитектура маркетплейса — цифровой платформы, на которой:

- продавцы размещают товары
- покупатели просматривают каталог
- пользователи оформляют заказы
- выполняется обработка платежей
- отправляются уведомления о статусах заказов
- формируется персонализированная лента товаров

Бизнес-логика в рамках задания не реализуется. Основная цель — архитектурное проектирование и контейнеризация одного сервиса.

## Архитектурный стиль

Выбран подход:
**Microservices + REST + Event-Driven Architecture**

### Причины выбора

- Независимое масштабирование доменов (каталог, заказы, платежи)
- Изоляция данных (Database per service)
- Возможность асинхронной обработки событий
- Соответствие принципам Service-Oriented Architecture

## C4 Model

### Level 1 — System Context

Marketplace Platform взаимодействует с:

- **Buyer** (покупатель)
- **Seller** (продавец)
- **Payment Provider** (внешний платёжный сервис)
- **Notification Provider** (Email/SMS сервис)

Диаграмма: [docs/architecture.puml](docs/architecture.puml)

### Level 2 — Container Diagram

Система разделена на следующие контейнеры:

- API Gateway
- Auth Service
- User Service
- Product Catalog Service
- Order Service
- Payment Service
- Recommendation Service
- Notification Service
- Message Broker
- Отдельная БД для каждого сервиса

### Персонализация

Реализуется через **Recommendation Service**.

**Источники данных:**

- история заказов
- просмотры товаров
- популярные товары
- категории пользователя

Сервис подписывается на события:

- `order.created`
- `payment.completed`
- `product.viewed`

**Результат:** REST endpoint возвращает персонализированную ленту товаров.

## Архитектурные решения (ADR)

### 1. Microservices

**Причина:** разделение бизнес-доменов и независимое масштабирование.

### 2. Database per Service

**Причина:** слабая связанность и автономность сервисов.

### 3. Event-Driven коммуникация

Используется для:

- уведомлений
- обновления рекомендаций
- реакций на оплату

**Причина:** асинхронность и отказоустойчивость.

### 4. API Gateway

**Причина:** единая точка входа, централизованная маршрутизация.
